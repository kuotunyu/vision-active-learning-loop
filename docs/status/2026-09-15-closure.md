## 8. 測試套件整理（2026-09-15）

- 全套 `pytest` 從 2026-09-09 的「773 passed、569 failed」變成「997 passed、17 skipped、0 failed」（153 秒）。
- 569 個失敗全來自兩個 Wave 0 啟動器測試檔找不到 `pwsh`（PowerShell 7）；現在這兩檔在 PATH 沒有 `pwsh` 時用 `pytest.skip(allow_module_level=True)` 整檔 skip，理由可見。
- 另外發現一個 v0.2.1 之後才出現的失敗：`tests/probes` 的 TF32 測試刪掉 `CUBLAS_WORKSPACE_CONFIG` 後呼叫 `configure_determinism`，假設 CUDA 尚未初始化；但 `tests/lite/test_baseline.py::test_baseline_main_records_a_fit_failure_on_disk` 在它之前先初始化了 CUDA（用一個記錄第一次初始化的 pytest plugin 找到的）。改法：CUDA 已初始化時改為設定工作區再呼叫，只驗證不設定；`configure_determinism` 本身沒有改。
- 一個雙程序競賽測試（`tests/artifacts/test_receipts.py`）在機器同時跑 robocopy 與雜湊比對時超過 20 秒 join 而失敗，單獨重跑與空閒時全套都通過；沒有改它。
