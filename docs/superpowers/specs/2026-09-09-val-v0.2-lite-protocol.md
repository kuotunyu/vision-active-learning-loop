# Vision Active Learning Loop v0.2-lite 協定

狀態：owner 於 2026-09-09 核可。本文件是復活方案第 2–7 步的規範來源。實作過程中凍結的細節以「以下在實作時凍結」段落回填。
上游：[2026-08-23 設計規格](2026-08-23-vision-active-learning-loop-design.md)（下稱 v0.1）與 [2026-09-09 復活評估](../../status/2026-09-09-revival-assessment.md)。

## 0. 一句話

在 RDD2022 Czech 子集上，用固定的 RT-DETR-R18 四類偵測器，比較 random / entropy / margin 三種選樣在 2%、5%、10%、20% 影像預算下的凍結測試集 mAP，單機、單 seed 起步、每個 fit 有收據。

### 2.2 manifest

- `item_id = SHA256(影像檔位元組)`（沿用 v0.1 §4.1）。
- 完全重複：同一 `item_id` 只保留一筆，其餘記為 alias。
- `split_group_id = item_id`。Czech 檔名為連續編號，沒有路線或拍攝段資訊；此為 v0.1 §4.1 第 7 條的 fallback，data card 記錄 fallback 率為 100%。
- 標註：PASCAL VOC XML → 每框 `(class_id, x_min, y_min, x_max, y_max)`。類別對應 `D00→0, D10→1, D20→2, D40→3`；其他標籤（如 D43、D44、D50）的框捨棄並計數。沒有有效框的影像保留為負樣本並計數。
- manifest 為一個 JSON，含 `schema_version`、來源 zip SHA-256、影像數、框數、各類別框數、alias 數、捨棄框數、負樣本數，以及每筆 `item_id, width, height, split, boxes`。manifest 的 canonical SHA-256 是後續所有收據的 `manifest_sha256`。
- 影像實體只以 `item_id` 查找；策略程式看不到檔名與 XML 路徑。

以下在實作時凍結，全部 fail-closed（停止並報錯，不靜默略過）：

- 影像尺寸以影像位元組為準，並要求與 XML `<size>` 完全相同；不一致即失敗。
- 只有「未知標籤」的框會被捨棄並計數。座標非整數、退化框（`x_max <= x_min` 或 `y_max <= y_min`）、超出宣告尺寸的框，都是失敗而非捨棄。若真實 Czech 資料含退化框，需以協定修訂新增一條計數捨棄規則，不得就地放寬。
- 影像與標註以檔名主幹配對；任一方缺對應即失敗。
- 完全重複（位元組相同）保留相對路徑字典序最小的一筆；若重複影像的標註不一致即失敗。
- 公開視圖是 `{schema_version, manifest_sha256, images:[{item_id, width, height}]}`，只含 pool 列且不含任何框。

### 2.3 切分（凍結）

```text
r = uint64(SHA256("val-loop-split-v1" || split_group_id)[0:8]) mod 10000
0000–1999 → test（凍結，20%）
2000–9999 → pool（80%）
```

- 沿用 v0.1 §4.2 的字串與雜湊，只把 pilot 區間併入 pool。
- 位元組編碼在此凍結：`SHA256(b"val-loop-split-v1" + split_group_id_utf8)`，取摘要前 8 位元組以 **big-endian** 解為 uint64，再對 10000 取模。`r = 1999` 是 test，`r = 2000` 是 pool。
- 切分後做一次覆蓋審核：test 每一類至少 20 個框，pool 至少 1,500 張影像。不符則停止並回到本文件修訂，不重抽。
- test 影像與標籤只給評估命令讀；訓練與選樣命令的輸入 manifest 是去掉 test 列與所有 pool 標籤的公開視圖。

## 3. 模型與訓練

- 偵測器：`PekingU/rtdetr_r18vd` revision `cc5b50f32f0100caaa3bd275343e2fb17762c73d`，經 `assets verify` 的快取。
- 四類 reset：每個 fit 開始時呼叫既有 `reset_four_class_head(model, seed=17)`，所有 arm、所有預算共用同一個 reset 後的初始狀態（`model_sha256` 記入收據並要求相等）。
- 前處理：沿用 Wave 0 processor 契約（最長邊 640、右下零填充到 640×640、rescale 1/255、不 normalize）。
- 增強：seed 決定的水平翻轉 p=0.5；亮度／對比／飽和度抖動 ≤ 0.1。無 mosaic、mixup、random crop。
- 優化：AdamW，detector lr 1e-4、backbone lr 1e-5、weight decay 1e-4；沿用既有 `build_optimizer`。
- 排程：固定 1,000 個優化步，前 50 步線性 warm-up，之後 cosine 到 0；batch 8；BF16 autocast；梯度範數 clip 0.1。
- 取樣：seed 決定的 shuffle，跨 epoch 循環直到 1,000 步；記錄有序 item_id 摘要。
- 決定性：`torch.use_deterministic_algorithms(True)`、cuDNN benchmark 關、TF32 關、`CUBLAS_WORKSPACE_CONFIG=:4096:8`；`grid_sampler_2d_backward_cuda` 的 warning 以 A3 的 allowlist 方式計數而非中止。
- checkpoint：只存最後一步，用既有 `save_checkpoint_atomic`；不做 early stopping，不用 test 選 checkpoint。
- 1,000 步是初始值。第 5 步（2% 基線 fit）跑完後可依 §8 的 loss 門檻調整一次，調整後所有 fit 重跑，並在收據記錄新值。

以下在實作時凍結：

- **框的座標系**：pinned processor 產生的框是對 **padded 640×640 畫布** 正規化的 cxcywh，不是對原圖（已用 320×640、640×320、100×50 三個案例實測確認）。反算回原圖像素用 `scale = 640 / max(原寬, 原高)`，再裁切到影像邊界。
- **增強的決定來源**：每個樣本取 `SHA256(b"augment" + 十進位 seed + 十進位 epoch + item_id)`，把前 32 位元組切成四段 big-endian uint64 除以 2^64 得四個 uniform，依序決定翻轉（< 0.5）與亮度／對比／飽和度係數（`0.9 + 0.2u`）。不使用全域 RNG，因此與批次大小、批次順序、平行度無關。
- **取樣順序**：每個 epoch 以 `(SHA256(b"sampler" + seed + epoch + item_id), item_id)` 排序。只產生完整批次；一個 epoch 尾端不足一批的樣本留到下一個 epoch 重洗後再用。
- **學習率排程**：warm-up 為 `(step + 1) / 50`（step 0 得 0.02、step 49 得 1.0）；其後 `0.5 * (1 + cos(pi * (step - 49) / 950))`，step 999 得 0。
- **CUDA warning allowlist**：訓練迴圈不綁定裝置，由呼叫端以 `backward_runner` 注入既有的 `run_allowlisted_backward`（預期 9 個 `grid_sampler_2d_backward_cuda`）。若第 5 步實測的次數不是 9，屬協定修訂事項，不得就地放寬。

## 4. 實驗迴圈

### 4.1 預算

```text
N = pool 影像數
B(p) = ceil(p × N), p ∈ {0.02, 0.05, 0.10, 0.20}
```

預算是累積且巢狀的：每個 arm 在 B(p) 的已獲取集合包含它在前一預算的集合。單位是影像；獲取一張影像即揭露它的全部有效框（含零框）。

### 4.2 共享起點（每 seed 一次）

以 `SHA256("initial" || seed || item_id)` 升冪排序 pool，取前 B(0.02) 張，訓練一個 fit。這個集合與 checkpoint 由三個 arm 共用。

### 4.3 每輪

對每個 arm、每個後續預算 p（5%、10%、20%）：

1. 用前一預算的 checkpoint 對所有未獲取影像打分（§5）。
2. 取分數最高的 `B(p) − B(p_prev)` 張，平手以 `item_id` 升冪。
3. oracle 揭露這些影像的框，寫入該 arm 的 ledger（`round, rank, item_id, score`）。
4. 從預訓練底重新 reset、重新訓練一個 fit，訓練集是該 arm 目前全部已獲取影像。

fit 數：`1 + 3 × 3 = 10`（每 seed）。

### 4.4 評估

所有 fit 完成後，`lite evaluate` 一次讀取全部 10 個 checkpoint 與凍結 test，輸出指標表。訓練與選樣命令沒有讀取 test 的程式路徑；測試以「test 標籤內容改變不影響 ledger」證明。

## 5. 選樣策略

輸入只有：未獲取影像位元組、已獲取 `item_id` 集合、前一預算 checkpoint、要求的張數。輸出是不重複的有序 `item_id` 清單。

- **random**：第一個後續回合以 `SHA256("random" || seed || item_id)` 排一次全序，之後每回合取該序的下一段（v0.1 §7.2）。
- **entropy** 與 **margin**：v0.1 §7.3 原式。每 query 由 `RawDetectorOutput` 的 `logits`、`final_boxes`、`penultimate_boxes` 算 `P_q`（背景 + 四類）、`o_q`、`l_q = 1 − IoU(final, penultimate)`；影像分數是 300 個 query 中最高 20 個 query 分數的平均。不做 threshold、NMS、postprocessor。
- 手算測試（沿用 v0.1 §7.3 列的八個案例）在合成 logits 上以 CPU 驗證。

排序雜湊的位元組編碼在此凍結：`SHA256(prefix_utf8 || decimal_seed_ascii || item_id_utf8)`，例如 seed 17 與 `item-a` 的 random 鍵是 `SHA256(b"random" + b"17" + b"item-a")`。排序鍵是 `(digest, item_id)`。同一編碼用於 §4.2 的 `initial` 前綴。分數以 float64 計算，模型的 float32 輸出在進入公式前上轉。

## 6. 指標與產出

- pycocotools：IoU 0.50:0.05:0.95、area all、maxDets 100。每個 fit 報 mAP50–95、AP50、四類 AP50–95、四類 recall。
- 偵測輸出：對 300 個 query 取 `sigmoid(logits)` 的最大類別分數，依分數保留前 100 個，框由 `final_boxes` 轉回像素座標；不做 NMS。
- 曲線：橫軸已獲取影像數與比例、縱軸 mAP50–95，三條 arm；2% 點標示為共享。
- `nAUBC = trapz(mAP, p from 0.02 to 0.20) / (0.20 − 0.02)`；報每 arm 的 nAUBC 與 arm − random 的差。
- 產出檔：`metrics.csv`（fit × 指標）、`ledger-<arm>.json`、`curve.png`、`experiment-receipt.json`。這四個與 manifest 摘要可進 Git；影像、XML、checkpoint、per-image 預測不進 Git。

以下在實作時凍結：

- pycocotools 的 `category_id = class_id + 1`；類別 id 0 不使用。
- 若凍結 test 的某一類沒有任何 ground truth，評估直接失敗（§2.3 的覆蓋審核應已先擋下）。
- 完全沒有偵測時，mAP 與 recall 記為 `0.0`，不回傳 pycocotools 的 `-1` 哨兵值。
- nAUBC 只接受依序完全等於 `(0.02, 0.05, 0.10, 0.20)` 的四個預算點。

## 7. 可重現性宣稱

允許的說法：「在本機（RTX 4090、driver 與套件版本記於收據）以固定 seed 執行；同機同 seed 單步重播的離散度已由 66 對副本量化，模型更新 relative L2 最大 6.4e-2、cosine defect 最大 2.0e-3，來源是 CUDA `grid_sample` backward 的 atomicAdd 累加順序。」

禁止的說法：deterministic、bitwise reproducible、跨 GPU／driver／版本可重現、人工標註成本節省。

每個 fit 的收據綁定：source commit、`manifest_sha256`、arm、seed、預算、已獲取 `item_id` 清單摘要、`model_sha256`（reset 後）、超參數、步數、最終 loss、峰值 VRAM、checkpoint SHA-256、環境觀察。收據用既有 `atomic_write_receipt`，同路徑不覆寫。

## 8. 門檻與停止規則

| 門檻 | 要求 | 不符時 |
|---|---|---|
| 覆蓋審核 | §2.3 兩條 | 停止，修訂本文件 |
| 基線 fit | loss 有限；前 10% 步中位數 > 後 10% 步中位數 | 調整 §3 步數一次後重跑；再不符停止 |
| 策略分數 | entropy、margin 在 ≥ 100 張未獲取影像上標準差 ≥ 1e-6 | 停止，檢查前向契約 |
| 預算 | 每個 ledger 張數精確等於 B(p)，`item_id` 不重複，巢狀 | 硬錯誤 |
| 記憶體 | 峰值配置 ≤ 22 GiB | 硬錯誤 |
| 評估順序 | 10 個 checkpoint 齊全後才允許 `lite evaluate` | 硬錯誤 |

看過 test 結果之後改動 §2–§5 任何一項，必須換新的 `experiment_id` 並全部重跑；不允許只重跑一個 arm。
